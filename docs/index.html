A downloaded AppImage that just works.

No chmod, no hunting for a folder, no hand-written menu entry, no missing icon. ifhai turns the file you downloaded into a real app with one command.

By hand~9 steps
chmod +x Obsidian-1.8.9.AppImage
mkdir -p ~/Applications ~/.local/{bin,share/applications}
mv Obsidian-1.8.9.AppImage ~/Applications/
~/Applications/Obsidian-1.8.9.AppImage --appimage-extract
cp squashfs-root/obsidian.png ~/.local/share/icons/…
sed -e 's|^Exec=.*|Exec=…|' … > ~/.local/share/…
# …and quote the path, or it breaks on spaces
ln -s ~/Applications/Obsidian-… ~/.local/bin/obsidian
update-desktop-database ~/.local/share/applications
ifhai install ~/Downloads/Obsidian-1.8.9…1 command

What the one command does.

Makes it executable and puts it somewhere sensible.The file is validated as an AppImage, then moved into a visible ~/Applications so nothing is left in Downloads.

Writes a menu entry that actually launches.The app's bundled .desktop file is rewritten, not copied: Exec points at the real launcher, paths are quoted correctly, and there is exactly one entry per app.

Finds the icon.The best icon in the AppImage is installed at the right size, so the app has one in the menu and the dock.

Adds a command.obsidian works in a terminal. If ~/.local/bin is not on your PATH it tells you the exact line to add.

Sorts out FUSE.Old runtimes need FUSE 2 and every runtime needs fusermount. If the system cannot run the file directly, the app is unpacked once and run from there. Nothing to install.

Undoes itself on failure.Everything is staged, then committed with an undo, so a failure leaves your download, your menu and any previous version exactly as they were.

Then it looks after it.

Upgrade without duplicates.Install a newer file of the same app and it upgrades in place, one menu entry, the old version kept for ifhai rollback.

Updates from where it came from.ifhai update finds a source from the AppImage's own update information, the URL a browser recorded on the download, or the repo named in its metadata (used only after the release is verified to match).

Install by name.ifhai install obsidian searches the AppImageHub catalogue and checks each candidate's real release first, so projects that stopped publishing are never offered.

Double-click installs.An "Install with ifhai" entry appears in the file manager's Open With list for AppImage files. It is never made the default.

Exact removal.ifhai remove deletes what ifhai created and nothing else, and refuses any path outside its own folders even if its record is damaged.

Says what is wrong.ifhai doctor explains missing FUSE, a command not on your PATH, duplicate menu entries from other tools, and Electron sandbox problems. It reports; it never deletes.

Measured, not claimed.

Nothing here is faster in a way you would notice: both ways take milliseconds. The case for ifhai is fewer steps, fewer silent failures, and what happens after the install. Measured on a 2020 laptop; method and scripts are in docs/DATA.md.

Careful by default.

  • HTTPS only, verified when possible.If GitHub or the publisher gives a SHA-256, the download is checked and the plan says so. If not, the plan says unverified and you decide. A checksum from the same release catches corruption, not a compromised repository.
  • It runs the file's own runtime to read it.To get the name and icon, ifhai runs the AppImage's runtime with --appimage-extract after you confirm. That is what every AppImage manager does. Only install files you trust.
  • No root, no daemon.Everything lives in your home directory, and nothing runs in the background.
  • No knobs.No config file. The options are --yes, --keep and --no-color. It decides the rest.
